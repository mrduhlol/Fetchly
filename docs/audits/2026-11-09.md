Existing release configuration enables minification/resource shrinking; published artifacts are debug builds, so that configuration does not currently demonstrate the savings.

## Prioritized source findings (not runtime exploit/reproduction claims)

1. **High: Python networking bypasses the direct client's private-address protection.** `OnDeviceMediaRepository.kt:38–45` falls through to the engine after an unclaimed/failed direct probe. `PublicOnlyDns.kt:16–20` protects OkHttp, while `fetchly_yt.py:114–119` uses yt-dlp's own networking. A hostname resolving privately or redirecting to LAN needs consistent validation across both paths. No external exploit was attempted.
2. **Medium: cancellation during assembly may overlap a resumed native session.** `DownloadWorker.kt:487–492` requests FFmpeg cancellation then exits without waiting for the completion callback used at line 473. Resumed work reuses the output name at line 432. The Kotlin run gate alone does not establish that native output has stopped. Needs a targeted runtime regression.
3. **Medium: valid conversion may fail the truncation heuristic.** MP4 may transcode non-AAC audio at `DownloadWorker.kt:443–452`; verification at `525–534` can compare transformed output bytes against exact source bytes. A valid output with substantially smaller encoded audio can be rejected. Test representative sources before changing the heuristic.
4. **Medium: progress cost grows with all history.** Every 500 ms `DownloadWorker` saves progress. `HistoryDao.kt:11–12` observes all rows, `HistoryRepository.kt:23–24` maps them all, and `AppGraph.kt:87–92` subscribes for process lifetime. Downloads also filters/sorts history during composition (`DownloadsScreen.kt:77`). This unnecessary work is code-confirmed; its frame-time impact is not measured.
5. **Medium: paused-state contrast and short-window details layout**, described above.

## Limits and next validation

No controlled physical low-end-phone, cold-launch, thermal, battery, long-duration throughput, background process-death, notification visibility, or repeated native-conversion pause/resume benchmark was completed. Unit coverage includes pause/resume ordering and partial-file retention; it is not proof of every end-to-end transition. Prioritize consistent network protection, native cancellation completion, progress/history isolation, and a physical-device benchmark with at least 10 fresh fetches per supported source and larger transfers. This audit makes no claim of “instant” downloading or universally fast fetching.
