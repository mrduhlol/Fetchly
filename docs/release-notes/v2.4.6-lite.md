# Fetchly Lite 2.4.6-lite

First production-signed Fetchly Lite APK, distributed directly as `fetchly-lite.apk` through GitHub Releases. It uses the existing persistent Fetchly signing certificate, pinned in `docs/SIGNING_CERT_SHA256`. No development APK or temporary signing key is promoted to this release.

## Downloads

- Stable APK: [fetchly-lite.apk](https://github.com/mrduhlol/Fetchly/releases/latest/download/fetchly-lite.apk).
- Android 10 (API 29) or later, 64-bit ARM (`arm64-v8a`) phones.
- Stable application ID: `com.fetchly.app.lite`; it installs alongside Fetchly.
- Published size, SHA-256, signing certificate and build commit: [release metadata](https://github.com/mrduhlol/Fetchly/releases/latest/download/fetchly-lite-release.json).
- APK checksum: [fetchly-lite.sha256](https://github.com/mrduhlol/Fetchly/releases/latest/download/fetchly-lite.sha256).

## Included

Home, Downloads and Library; automatic link detection; a thumbnail and real format/quality dialog; MP3-only audio choices; selectable attachments when a post's extractor exposes multiple items; Android share-to-download; and one download at a time. The approved Greek pottery artwork, Hermes branding and welcome animation are unchanged.

## Test-build separation

New test APKs use `com.fetchly.app.lite.test`, a `-test` version suffix and a development signer. They are Actions artifacts, not stable release downloads. They can coexist with the stable APK.

The earlier Actions test APK used `com.fetchly.app.lite` with a different certificate. If that build is installed, remove that earlier Lite test app before installing this first production-signed release. Uninstalling clears in-app history and preferences; downloaded media files remain on the device. This does not require uninstalling the full Fetchly app.

## Verification scope

Release automation runs Kotlin unit tests, Python bridge tests and lint, then verifies the production APK's signer against the pinned certificate, package/version, non-debuggable manifest and ARM64 architecture before publishing. Source restrictions and extractor support still apply. Device UI and live multi-site download coverage are documented in [Lite verification limits](../lite/README.md#size-and-verification-limits).
