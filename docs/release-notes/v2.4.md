# Fetchly 2.4

- Download startup reuses the stream URLs, request headers and fragment metadata found by Fetch instead of extracting the page again for each stream. Failed transfers invalidate cached metadata so expired links can refresh.
- Repeated previews reuse a successful result for up to 30 seconds, with a bounded in-memory cache, and common extractor code warms up off the UI thread without network requests. First-time source response and Android scheduling still affect startup time.

- Pause preserves yt-dlp partial files and fragment checkpoints. Resume continues retained data when the source supports it; a real HTTP transfer regression test checks that resuming sends a Range request from the saved byte offset.
- Paused downloads stay in the active list with their stored percentage and byte counts. Their content and progress bar dim, and the thin Pause control becomes a green outlined Resume icon.
- YouTube size parsing now reads byte counts embedded in playlist URLs, and audio ranking no longer lets unknown HLS metadata hide a known combined video/audio size. Estimates remain marked; sources that supply no size information cannot have an exact size promised.
- Home has a larger fetch panel, translucent platform-logo pebbles, a more subdued wallpaper, scrolling content, and a black gradient copyright footer.
- Library uses newly generated lyre-and-parchment artwork.
- Transfer notifications use media thumbnails on the right. A soundless default-importance channel allows status-bar visibility; Android and the user's notification settings still control what is displayed. Small Moai icons are monochrome adaptations of Noto Emoji artwork, with a sunglasses variant on completion.
- Download progress is persisted in the database. A non-destructive schema migration preserves existing download history.

## One-time reinstall required from v2.3

The older release workflow restored a key at a default path while Gradle could use a different XDG path. The published v2.3 certificate differs from the persistent release key. Android cannot update that installation in place: uninstall the old app before installing this corrected v2.4 APK. Uninstalling clears settings and in-app history; back up anything needed first.

Version 2.4 explicitly selects the persistent signing store and refuses publication unless the APK certificate matches `docs/SIGNING_CERT_SHA256`. Future releases using that pinned key can update in place.

Android restricts status-bar icons to monochrome; it cannot display the full-color emoji there.

Partial media files already deleted by 2.3 cannot be recovered by this update. The corrected resume behavior applies to partial data retained by 2.4.

Verification: 252 JVM tests and 32 Python tests pass, including real-engine cached startup and HTTP Range resume. Android lint and APK build pass. The updated native app reached Home, but the device-hub screenshot service failed, so rendered visual verification remains incomplete.
