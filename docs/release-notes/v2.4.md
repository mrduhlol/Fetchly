# Fetchly 2.4

- Pause preserves yt-dlp partial files and fragment checkpoints. Resume continues retained data when the source supports it; a real HTTP transfer regression test checks that resuming sends a Range request from the saved byte offset.
- Paused downloads stay in the active list with their stored percentage and byte counts. Their content and progress bar dim, and the thin Pause control becomes a green outlined Resume icon.
- YouTube size parsing now reads byte counts embedded in playlist URLs, and audio ranking no longer lets unknown HLS metadata hide a known combined video/audio size. Estimates remain marked; sources that supply no size information cannot have an exact size promised.
- Home has a larger fetch panel, translucent platform-logo pebbles, a more subdued wallpaper, scrolling content, and a black gradient copyright footer.
- Library uses newly generated lyre-and-parchment artwork.
- Transfer notifications use media thumbnails on the right. A soundless default-importance channel allows status-bar visibility; Android and the user's notification settings still control what is displayed. Small Moai icons are monochrome adaptations of Noto Emoji artwork, with a sunglasses variant on completion.
- Download progress is persisted in the database. A non-destructive schema migration preserves existing download history.

The signing key is unchanged from the published 2.1–2.3 APKs, so those installations can update in place. Android restricts status-bar icons to monochrome; it cannot display the full-color emoji there.

Partial media files already deleted by 2.3 cannot be recovered by this update. The corrected resume behavior applies to partial data retained by 2.4.
